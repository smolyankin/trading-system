# TradingSystem - Система Агрегации Торговых Тиков в Реальном Времени

Высокопроизводительная система на ASP.NET Core для агрегации торговых тиков в реальном времени от множественных WebSocket-источников, нормализации различных JSON-форматов, дедупликации сообщений и сохранения данных в PostgreSQL с полной отказоустойчивостью и автоматическим переподключением.

## Функциональность

- **Мульти-источниковая Агрегация**: Подключается к трём независимым WebSocket-источникам с различными JSON-форматами
- **Нормализация Данных**: Преобразует гетерогенные JSON-форматы в унифицированную структуру `NormalizedTick`
- **Дедупликация**: Фильтрует дубликаты сообщений в течение 1-секундного окна
- **Пакетная Обработка**: Эффективная вставка в базу данных с батчингом (100 тиков или таймаут 50мс)
- **Отказоустойчивость**: Автоматическое переподключение с экспоненциальной задержкой (1с → 2с → 4с → 8с → 16с → 30с максимум)
- **Статистика в Реальном Времени**: HTTP GET эндпоинт `/stats` возвращает общее количество обработанных тиков
- **Поддержка Docker**: Полная контейнеризация с Docker Compose для 5 сервисов

## Технологический Стек

- **.NET 10.0** с ASP.NET Core
- **PostgreSQL 15** для хранения данных
- **Entity Framework Core 10** для доступа к базе данных
- **System.Threading.Channels** для паттерна производитель/потребитель
- **WebSocket** с автоматическим переподключением
- **xUnit & Moq** для тестирования (TDD подход)

## Необходимые Требования

- .NET 10.0 SDK
- Docker & Docker Compose
- PostgreSQL 15 (или Docker)

## Быстрый Старт

### Использование Docker Compose (Рекомендуется)

1. Клонируйте репозиторий:
   ```bash
   git clone https://github.com/smolyankin/trading-system.git
   cd trading-system
   ```

2. Запустите все сервисы:
   ```bash
   docker-compose up -d
   ```

3. Сервисы будут доступны по адресам:
   - **Aggregator API**: `http://localhost:8080`
   - **Статистика**: `http://localhost:8080/stats`
   - **Эмиттер 1** (Формат 1): `ws://localhost:8081`
   - **Эмиттер 2** (Формат 2): `ws://localhost:8082`
   - **Эмиттер 3** (Формат 3): `ws://localhost:8083`
   - **PostgreSQL**: `localhost:5432`

## Документация API

### Эндпоинты

- **GET /stats** - Возвращает общее количество обработанных тиков

### WebSocket Эмиттеры

Все эмиттеры транслируют торговые тики в реальном времени (100 тиков в секунду по умолчанию):

**Эмиттер 1** - Стандартный Формат
```json
{
  "symbol": "BTCUSDT",
  "price": 50000.12,
  "quantity": 0.01,
  "time": 1623456789000
}
```

**Эмиттер 2** - Расширенный Формат
```json
{
  "ticker": "ETHUSD",
  "lastPrice": 3500.50,
  "volume": 0.10,
  "timestamp": "2025-03-12T10:30:00Z"
}
```

**Эмиттер 3** - Компактный Формат
```json
{
  "s": "SOLUSDT",
  "p": 150.25,
  "v": 5.0,
  "t": 1741795200000
}
```

## Тестирование

### Ручное тестирование

После запуска сервисов в docker
- Получить статистику по эндпоинту `/stats` и убедиться, что количество обработанных тиков увеличивается
- Прочитать логи в контейнерах
- Открыть таблицу ticks в базе данных

## Возможные Улучшения

### Архитектура

1. **Микросервисы**: Раздельные сервисы для агрегации и статистики
2. **Брокер Сообщений**: RabbitMQ или Kafka для асинхронной обработки тиков
3. **Кеш**: Redis для часто запрашиваемой статистики и последних тиков
4. **Трейсинг**: OpenTelemetry для отслеживания запросов

### Функциональность

1. **Множественные Эмиттеры**: Динамическая регистрация и обнаружение эмиттеров
2. **WebSocket Аутентификация**: Защищённые WebSocket соединения с токенами

### Инфраструктура

1. **Health Checks**: Эндпоинт `/health` с проверкой зависимостей
2. **Метрики**: Prometheus метрики для скорости обработки тиков, ошибок, задержек
3. **Мониторинг**: Grafana дашборды для наблюдаемости системы
4. **Агрегация Логов**: ELK стек для централизованного логирования

### Отказоустойчивость

1. **Circuit Breaker**: Паттерн для отказов подключения к базе данных
2. **Политики Повтора**: Polly или аналоги для обработки временных сбоев
